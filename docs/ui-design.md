# 界面设计规范

本规范整理自用户于 2026-11-01 确认的要求。适用于 SolidCraft Roller Seal 的界面设计和后续维护；不代表授权自动重做未要求修改的其他客户端。

## 1. 风格与优先级

使用专业桌面工程软件的视觉语言，深色主题参考 VS Code。优先保证信息密度、操作效率、文字可读性和视觉一致性。顶栏、参数表、输出区、弹窗使用同一套颜色与控件规则。

- 主体为炭黑、中性冷灰和白灰；蓝色只用于主操作、选中、焦点与进度等有意义状态。
- 禁止绿色、青绿色背景和其他无关色调污染；用户指定的冷灰色值为深色主题依据。
- 禁止渐变、玻璃拟态、发光边框、大圆角卡片、胶囊形堆叠控件、无意义图标与装饰。
- 禁止套用常见 SaaS Dashboard 风格；通过对齐、字号、留白与分隔线组织工程参数和操作。
- 错误可以用克制的红色文字或图标表达，不因此增加大块彩色背景。

## 2. 主题与配色

必须同时保留浅色、深色模式，默认跟随系统 `prefers-color-scheme`。网页、输入控件、弹窗、浏览器主题色一起切换。禁止固定深色后删掉浅色主题。

### 深色模式：用户指定基础色

| 用途 | 色值 |
| --- | --- |
| 主背景 / 工作区底色 | `#111318` |
| 面板背景 | `#1A1D23` |
| 输入框 / 数值编辑区背景 | `#242830` |
| 常规边框 / 分隔线 | `#343940` |
| 主文字 | `#E5E7EB` |
| 次要文字 | `#9CA3AF` |
| 强调色 / 选中 / 焦点 / 进度 | `#3B82F6` |

颜色必须分配到明确层级，不能把表头、输入区和大块空白区全部刷成同一档灰色：表格空白区用主背景，表头与操作区用面板背景，数值编辑区用输入背景。

### 浅色模式

| 用途 | 色值 |
| --- | --- |
| 主背景 | `#F3F3F3` |
| 面板 / 输入背景 | `#FFFFFF` |
| 表头等次级表面 | `#F0F0F0`，可按层级使用面板白色 |
| 常规边框 | `#D4D4D4` |
| 主文字 | `#333333` |
| 次要文字 | `#616161` |
| 蓝色强调 | `#2563EB` |

### 主操作与状态

- 快速输出 DXF、快速输出 PDF、输出项目 ZIP 使用一致的按钮样式。
- 主操作使用深蓝 `#2563EB` 配白字；悬停 `#1D4ED8`、按下 `#1E40AF`。不要回到亮蓝底配黑字。
- 普通工具按钮使用中性灰表面；蓝色集中在主要操作和有效状态。
- 复选框的选中状态必须使用当前主题的蓝色，避免 iOS 原生控件呈现偏青颜色而破坏一致性。勾选标记必须清晰。
- 默认、悬停、焦点、禁用、错误状态须可辨；文字和控件保持足够对比度。

## 3. 形状、字号与密度

用户后续允许克制地增加圆角，当前约定如下；该条取代早期过于方正的 2px/3px 方案。

| 对象 | 圆角 |
| --- | --- |
| 按钮、输入框、顶栏、面板 | `4px` |
| 任务进度、密钥、参数检查弹窗 | `6px` |
| 复选框 | `3px` |
| 表格单元格、进度轨道、日志区 | 直角或保持利落边缘 |

- 标题统一写“标准辊密封生成”，注意“辊”“密封”的用字。标题比正文突出，当前桌面约 20px、手机约 19px。
- 正文、参数和按钮以紧凑清晰为准，通常 12–13px；数值使用便于对齐的等宽数字。
- 控件高度及间距以操作可达和信息密度为准，避免扩大字号和留白造成手机有效空间减少。
- 手机数字输入保留防 iOS 聚焦自动放大的处理，兼顾较小的视觉字号；不要为此禁止用户正常双指缩放。

## 4. 参数表与输出区

- 边距、对齐线与其他区域一致；不得为了增加边距在参数表外再套一层卡片。
- 操作列的删除按钮居中；手机操作列约 46px，编号约 60px，前几项数值列约 56px，在不拥挤的前提下减少横向滚动。
- 手机表格视口约容纳四行，当前上限约 220px，并按实际屏幕可用高度进一步收缩；桌面高度不得超过视口可用空间。避免把固定像素高度生硬套到所有设备。
- 手机隐藏“单位 mm / Excel、WPS 粘贴说明”页脚。
- 输出区只有快速输出与项目输出两个层级。项目格式保持 DXF、STEP、PDF、列表 CSV；不重新加入合并 STEP、冗余“输出设置”标题或无意义装饰箭头。
- 隐藏尺寸设置不等于丢弃数据：导入文件有值时保留，缺失或空白按业务默认值处理。

## 5. 弹窗与反馈

- 任务进度弹窗使用实色面板、可辨识的标题栏、边框和中性黑色遮罩；允许克制的黑色投影，不能使用发光描边或玻璃背景。
- 保留当前步骤、实际进度、取消/下载及可折叠日志。避免重复的“任务进度”“生成中”状态行和多余的步骤入口。
- 生成时自动打开任务弹窗，关闭后从顶栏重新进入；不使用挡住操作区的悬浮按钮。
- 进度以实际工作阶段为依据，结果可下载之前不能显示完全完成。
- 参数检查成功在页面中心短暂显示“没有错误”并自动关闭；存在错误时保持弹窗，供用户阅读并手动关闭。
- API Key 缺失或失效时用弹窗处理，正常进入不显示顶栏连接状态和常驻密钥输入框。

## 6. 实现与验收

- 优先用统一 CSS 变量维护配色，清理互相覆盖的旧主题规则；浅深色共用尺寸与布局。
- 界面变更至少核对 1440px 桌面、390px 手机、320px 窄屏，以及浅色、深色两种模式。
- 核对主背景、面板、输入、边框、文字、按钮、复选框和进度条的实际计算样式；只改 CSS 色号不代表整体视觉层次已改善。
- 检查页面无意外横向溢出，参数表可滚动，弹窗可在视口内操作，主要按钮与错误内容清晰可读。
- 对页面与弹窗截图做目视复核，报告真实执行的检查范围；自动化截图不能说成用户手机实机验收。
- 更新页面引用的样式版本，并核对实际服务返回的普通、gzip、Brotli 资源，防止源文件和压缩文件不一致。
- 更新规范时替换对应条目，避免继续追加互相矛盾的规则；保留明确的本地备份和回退路径。
